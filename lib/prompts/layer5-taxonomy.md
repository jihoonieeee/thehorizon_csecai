# Layer 4 — Taxonomy + LLM Understanding Prompt (reference)

> **This file is documentation only.** The live prompt is built inline in
> `lib/pipeline/understand/understandSource.js` via `buildSystemPrompt()`.
> The taxonomy registry is injected at runtime via `buildTaxonomyContextForPrompt()`.
> Do NOT edit this file expecting it to change runtime behaviour.

---

## Purpose

Enrich each source against the Validated AI Threat Taxonomy (June 2026). One LLM call per
source; idempotent (sources stamped `taxonomy-2026-06` are skipped).

Principle: **understand first, then tag**. The model reads and summarises before assigning
any tags. Tags are assigned only when the source substantively describes the threat behaviour.

---

## Runtime System Prompt Structure

```
[CORE PRINCIPLE]
Fewer, higher-confidence tags are always better than many uncertain ones.

[TAXONOMY CONTEXT — injected at runtime from taxonomyRegistry.buildTaxonomyContextForPrompt()]
  Four domains, 62 primary threat tags, 5 secondary dimensions.
  ~2500 tokens; cached in module scope; same for every source in a batch.

STEP 1 — UNDERSTAND THE SOURCE
  source_summary (2–3 analyst sentences), primary_subject (≤15 words),
  main_claims (2–5 facts), key_entities (≤10), important_numbers (≤5).

STEP 2 — ASSIGN SOURCE TYPE (one of 16 canonical strings)
  vulnerability, exploit_disclosure, incident, threat_intelligence,
  research_finding, defensive_capability, benchmark_evaluation,
  capability_demonstration, adversary_adoption_signal,
  infrastructure_dependency_signal, trust_boundary_shift,
  societal_harm_signal, governance_signal, ecosystem_signal,
  strategic_signal, unknown

  Disambiguation rules inline: vulnerability vs exploit_disclosure,
  incident vs threat_intelligence, research vs capability_demonstration, etc.

STEP 3 — PRIMARY DOMAIN (one of 5)
  traditional_ai_threats, llm_threats, agentic_ai_threats,
  ai_enabled_threats, unclear_or_adjacent.

STEP 4 — PRIMARY THREAT TAGS (primary_threat_tags[])
  Rules: use only taxonomy tags from the assigned domain; supporting_quote ≥ 20 chars;
  no keyword-only tagging; max 4 tags; return [] if unsure.
  Tag disambiguation embedded: prompt_injection hierarchy,
  jailbreak vs guardrail_bypass, model_extraction vs model_theft,
  data_poisoning vs model_poisoning, llm vs agentic domain split, etc.

STEP 5 — SECONDARY DIMENSIONS (secondary_dimensions[])
  Optional. Only: excessive_agency, misinformation, overreliance,
  resource_overload, cascading_hallucination.

STEP 6 — CATEGORY CANDIDATES (category_candidates[])
  1–3 suggestions. Each: { category, supporting_tags[], confidence, reason }.
```

---

## Output Schema (primary_threat_tags items)

```json
{
  "tag":               "string — from taxonomy registry",
  "domain":            "string — must match tag's domain",
  "supporting_quote":  "string — ≥20 chars verbatim from source",
  "reason":            "string — why this tag applies",
  "confidence":        "high | medium | low",
  "operational_attack_mapping": "string — ATT&CK technique (ai_enabled only)",
  "ai_capability_modifier":     "string — AI modifier (ai_enabled only)"
}
```

Post-processing (`validateAndNormalise`): all tags run through `taxonomyValidation.validateThreatTags`.
Rejected tags are dropped; weak/needs_manual_review are kept but flagged.
Cap: max 4 tags kept; extras silently dropped with stdout warning.

---

## Validation Status Outcomes

| Status              | Condition                                                     |
|---------------------|---------------------------------------------------------------|
| validated           | Tag in registry, domain match, quote ≥ 20 chars, not generic |
| weak                | Quote < 20 chars, or generic phrasing, or ai_enabled missing technique |
| needs_manual_review | Traceable source absent                                       |
| rejected            | Not in registry, wrong domain, or is a secondary dimension    |

---

## Token Budget (approx per source)

- System prompt (taxonomy + rules + disambiguation): ~3200 tokens input
- User prompt (title/publisher/date/text up to 3500 chars): ~1000 tokens input
- Output (understanding + tags + candidates): ~400 tokens
- Total: ~4600 tokens/source at `source_understanding` task profile
- Model: `gemini-2.5-pro` (dev/quality mode) or `gemini-2.5-flash` (cheap/local)
