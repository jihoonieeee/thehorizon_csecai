# The Horizon — API Reference

All endpoints are Vercel serverless functions under `/api/`. Auth for mutation endpoints: `Authorization: Bearer {CRON_SECRET}` header.

---

## GET /api/dashboard

Returns dashboard data for a reporting window.

**Query params:**
- `window` — `week | month | quarter | annual` (default: `quarter`)

**Response:**
```json
{
  "window": "month",
  "window_key": "2026-06",
  "window_label": "June 2026",
  "date_from": "2026-06-01",
  "date_to": "2026-06-30",
  "summary": {
    "total": 142,
    "high_trust": 38,
    "by_category": { "traditional_ai_threats": 31, ... },
    "other": 14
  },
  "categories": [
    {
      "key": "traditional_ai_threats",
      "label": "Traditional AI Threats",
      "source_count": 31,
      "top_sources": [{ "title", "url", "publisher", "date", "maturity", "summary" }],
      "evidence_maturity": { "operational": 2, "observed": 5, ... },
      "maturity_sources": { "operational": [...], "research": [...] },
      "assessment": "...",
      "insights": [{ "insight_id", "title", "insight_body", "explanation_points", "cited_sources" }],
      "coverage_gaps": [],
      "insights_from": null,
      "insights_stale": false
    }
  ],
  "trend": {
    "week_labels": ["Jun 9", ...],
    "by_category": { "traditional_ai_threats": [3, 5, ...] }
  },
  "top_incidents": [{ "title", "url", "publisher", "date", "category", "trust_tier", "maturity", "why", "summary" }],
  "top_sources_justified": true,
  "tag_matrix": {
    "tags": [{ "id", "label", "domain" }],
    "by_category": { "TAI01_data_poisoning": { "traditional_ai_threats": 4, ... } },
    "defense": { "TAI01_data_poisoning": { "traditional_ai_threats": 1 } },
    "sources": { "TAI01_data_poisoning": [{ "title", "url", "publisher", "date", "category" }] }
  }
}
```

**Notes:**
- Annual window uses 12 monthly trend buckets (Jul 2025 – Jun 2026). Other windows use 12 rolling weekly buckets.
- Insight data comes from the `dashboard_insights` table (generated by `scripts/generateDashboardInsights.js`). Falls back to the most recent prior period of the same window type if the current period hasn't been generated yet (`insights_stale: true`).
- `top_incidents` is LLM-curated (from `dashboard_insights._period_meta`) when available; falls back to deterministic importance ranking.
- PostgREST 1000-row cap is handled by paginated `selectAll()` internally.

## GET /api/dashboard?format=newsletter&window={week|month}

Returns the latest **pre-generated** newsletter for a window (public read). Newsletters are generated on a schedule by `generate-newsletter.yml` and stored via `saveNewsletter`. The dashboard Generate page reads this on load — there is no user-facing trigger.

**Response:** `{ html, period, sourceCount, insightCount, generated_at }` · `404` if not generated yet.

## POST /api/dashboard

**Development / testing only** — dispatches the `generate-newsletter.yml` workflow to (re)generate a newsletter on demand. Not called from the UI.

**Auth:** `Bearer {CRON_SECRET}` or `Bearer {GEN_TOKEN}`

**Body:**
```json
{ "format": "newsletter", "window": "week" }
```
Only `format=newsletter` is supported.

**Response:** `202 { queued: true, window, triggered_at }`

## GET /api/sources

Filterable source list.

**Query params:**
- `period` — `YYYY-MM | last-7d | last-30d | last-90d | all-time` (default: `all-time`)
- `category` — exact `main_category` value
- `trust_tier` — comma-separated list of tier values
- `search` — text search on title, publisher, short_summary (ILIKE)
- `limit` — max rows (default and hard cap: 5000)

**Response:**
```json
{
  "period": "last-90d",
  "period_label": "Last 90 days",
  "date_range": { "start": "2026-04-22", "end": "2026-07-21" },
  "count": 312,
  "sources": [
    {
      "id", "title", "url", "publisher", "author",
      "date_published", "date_collected", "date_confidence",
      "main_category", "trust_tier", "tags", "source_type",
      "short_summary", "analyst_brief", "reading_value", "maturity",
      "validation_status", "ai_specificity_score",
      "is_report", "is_child_source", "is_defensive",
      "parent_source_id", "parent_title", "finding_title", "finding_count",
      "all_categories", "needs_review", "starred",
      "label",
      "significance": { "level", "novelty", "reason" },
      "mechanism": { "exploit", "consequence", "rationale", "conflict" },
      "atlas": { ... },
      "report_analysis": { ... }
    }
  ]
}
```

**Notes:**
- `count` excludes child sources (parent_source_id set); represents parent-level items.
- `label` mirrors `reading_value` (essential/recommended/analyst/background); falls back from the top-level column to `intelligence.reading_value` for backward compat.
- `starred` column requires migration 013 to be applied; degrades gracefully if missing.
- All `reject` status sources are excluded. Child sources (digest findings) are included.

## PATCH /api/sources?id={id}

Edit source metadata.

**Auth:** `Bearer {CRON_SECRET}` only (not GEN_TOKEN).

**Body fields (any combination):**
- `starred: boolean` — star/unstar toggle
- `needs_review: boolean` — review flag
- `date_published: "YYYY-MM-DD"` — manually corrected date (sets `date_confidence=exact`, clears `needs_review`)
- `main_category: string` — one of the 5 valid categories; leaves `category_reason="Manual override (dashboard)"`
- `tags: string[]` — replaces tags array (max 50)
- `short_summary: string` — replaces summary (max 1000 chars)

**Response:** `{ ok: true, id, ...patch }`

## DELETE /api/sources?id={id}

Delete a source and its evidence rows.

**Auth:** `Bearer {CRON_SECRET}` only.

**Response:** `{ ok: true, deleted: "id" }`

## POST /api/agent

Chatbot query.

**Body:**
```json
{ "query": "What are the latest MCP attacks?", "history": [] }
```

**Response:**
```json
{
  "answer": "...",
  "sources": [{ "title", "url", "publisher", "date" }],
  "grounded": true,
  "plan": { ... }
}
```

When no relevant sources are found, `grounded: false` and `answer` is labelled as general knowledge.

## POST /api/refresh

Triggers a fresh ingest + classify cycle. Called by Vercel Cron at 22:00 UTC.

**Auth:** `x-vercel-cron: 1` header (Vercel internal) or `Bearer {CRON_SECRET}`.

---

## POST /api/backfill

Triggers a backfill ingest for a date range.

**Auth:** `Bearer {CRON_SECRET}`

**Body:** `{ start: "YYYY-MM-DD", end: "YYYY-MM-DD", connectors: "all" }`
